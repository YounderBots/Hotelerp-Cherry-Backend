# Master Page-by-Page Test Checklist

**Project:** Cherry Hotel ERP  
**Created:** 2026-09-24  
**Route source of truth:** `Frontend/src/App.jsx`, cross-checked against `Frontend/src/Sidemenu.js`, backend route inventory, and `Frontend/e2e/audit.mjs`.

## Inventory accounting

- **69 routed URL entries** extracted from `App.jsx` (64 protected application pages, 4 authentication routes, and the wildcard not-found route).
- **1 intentionally unrouted authentication surface** (`/authentication/otp`) is included below as a blocked/direct-URL check because the component exists and the client explicitly asked for hidden routes to be discovered.
- **70 page surfaces** are therefore tracked here. Dashboard tabs and modal/detail states are tested as part of their owning page and are called out in the API/data column where relevant.
- A page is not “passed” merely because it renders. Each row must have evidence for functional, responsive, API/data, and regression checks appropriate to that page.

## Required test protocol for every page

1. Open by sidebar/direct URL and verify auth redirect, route title, empty/error/loading states, and page boundary.
2. Exercise every visible button, icon-only action, menu item, link, dropdown, tab, filter, and pagination control.
3. For forms: empty, invalid type, boundary, duplicate, cancel/reset, repeated submit, and refresh/persistence.
4. For tables: search, filter, sort, pagination, empty result, row actions, refresh, and stale-state checks.
5. Inspect below-the-fold content, modals, file/image previews, print/export actions, and keyboard/focus behavior.
6. Capture browser console errors, failed requests, HTTP 4xx/5xx responses, and relevant response bodies; trace critical writes to backend/database behavior.
7. Repeat critical flows up to five passes where practical; record actual pass count.
8. Check desktop (1440), laptop (1024), tablet (768), and mobile (375) widths. Record overflow and unusable controls.
9. Recheck shared components after any shared fix and update the issue register before moving on.

Status values: `NOT STARTED`, `IN PROGRESS`, `PASS`, `PASS WITH P3`, `BLOCKED`, `FAIL`. Only `PASS`, `PASS WITH P3`, or `BLOCKED` may be left behind when a page has no unresolved P0/P1/P2 issue.
