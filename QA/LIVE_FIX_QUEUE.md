## P0

### LIVE-001 — Local and LIVE share one credential
- **Page:** authentication
- **Problem:** a password randomly generated by the LOCAL `seed_demo_data.py --confirm` run authenticates successfully against LIVE.
- **Evidence:** LIVE `:9010/login_post` returned 200 for `admin@cherryhotel.com` using the local-only seed password; the same value authenticates locally on `:8000`.
- **Root cause:** the two environments were provisioned from the same seed run / shared release dump, so one credential is valid in both.
- **Local fix required:** none possible in code — this is an environment-provisioning defect.
- **Action required:** rotate LIVE credentials to a value unique to LIVE, via
  `python Backend/tools/rotate_passwords.py --confirm`, and stop sharing release dumps containing
  live hashes. Confirm old password fails and new succeeds.
- **Test required:** verify LIVE-002 asset access with the new token; confirm no environment
  credential is valid in the other.
- **Regression scope:** authentication, C-066, readyz, preflight image check.
- **Status:** OPEN — owner action.

## P1

### LIVE-002 — Every uploaded image 404s on LIVE
- **Page:** `/room_view`, `/rooms`, `/employee`, `/room_incident_log`, `/menus`, `/bar_menus` — all upload consumers.
- **Expected:** room photographs, avatars, identity proofs, incident attachments and menu images render.
- **Actual:** all return 404. Room cards render with empty image slots.
- **Evidence:**

  | Probe | Result |
  |---|---|
  | LIVE `:9010` `/masterdata/templates/static/upload_image/<f>.jpg`, no token | 401 — route exists, auth required |
  | LIVE `:9010` same path, **valid Admin token** | **404** |
  | LIVE `:9010` `/templates/static/upload_image/<f>.jpg` + token | **404** |
  | LOCAL `:8000` `/masterdata/templates/static/upload_image/<f>.jpg` + token | **200 `image/jpeg`, 112020 bytes, JPEG magic verified** |
  | LOCAL `:8000` identity proof, no token | **401 (correctly protected)** |
  | LIVE `/masterdata/room` API | 200, returns correct stored paths |

- **Root cause:** **not a code defect.** The gateway route, the frontend URL construction
  (`useAuthedMedia(path, "/masterdata")` → `APICall.getBlobT`) and the token-bearing fetch are all
  correct and verified working locally. LIVE returns 404 for paths its own database still references,
  so the **upload files were never restored to LIVE's service static trees** — step 2 of the documented
  restore (`restore_uploads.py`) was skipped after the SQL load.
- **Local fix required:** **none.** Deliberately not worked around by copying or duplicating assets.
- **Action required (deployment):**
  ```bash
  python Backend/tools/restore_uploads.py --release 30-Sept-2026
  python Backend/tools/restore_uploads.py --release 30-Sept-2026 --verify
  ```
- **Local verification done:** all six asset classes fetch 200 with correct content-type through the
  local gateway, and identity proofs remain protected (401 without a token).
  Room photo `image/jpeg` · user avatar `image/png` · identity proof `image/jpeg` ·
  incident attachment `image/jpeg` · restaurant menu `image/jpeg` · bar menu `image/jpeg`.
- **Regression scope:** preflight check 6, `test_preflight_images.py`, `test_upload_content.py` (4 services).
- **Status:** ROOT CAUSE PROVEN — remediation is a deployment action.

## P2

### LIVE-004 — SPA returns 200 HTML for unknown asset paths
- **Page:** `:5700` static hosting
- **Expected:** a request for a missing asset returns 404.
- **Actual:** `/does-not-exist-xyz.jpg` → **200 `text/html`**, 728 bytes (the SPA `index.html`).
  Same for `/templates/static/upload_image/*.jpg`.
- **Evidence:** `Content-Type: text/html`, `jpegMagic=False`, identical byte length to `/`.
- **Root cause:** SPA history fallback serves `index.html` for all unmatched paths.
- **Impact:** no current client-visible defect — the app fetches assets via authenticated XHR and
  handles non-2xx explicitly. It does mask missing-asset 404s from casual HTTP checks, which is what
  made my first LIVE-002 reading wrong.
- **Local fix required:** optional. Restrict the fallback to HTML-navigation requests
  (`Accept: text/html`) so asset 404s surface properly.
- **Status:** OPEN — low priority, no code change made.

## Local fixes made this session

**None.** No source file was changed.

LIVE-002 was investigated as a candidate code defect and ruled out: the frontend gateway-prefix +
token-fetch architecture (`Frontend/src/hooks/useAuthedMedia.js`, `APICall.getBlobT`) and the

server has no files to serve.

sweep probe now waits for network/data settlement and uses exact token matching, which removed two
false-positive classes (racing data, and case-insensitive null scanning).
