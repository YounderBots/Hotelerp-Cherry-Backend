## Triage rules

1. P0/P1 findings are fixed before the affected page is marked complete.
2. A P2 page finding is either fixed/retested or recorded with an exact blocker and owner.
3. P3 polish may remain open only with explicit rationale; it does not block a **NOT READY** decision when it affects client usability.
4. No database cleanup, reseed, credential rotation, or production deployment is performed without explicit authorization and a verified backup.
5. Every state change in this register must be accompanied by an evidence path in `QA/QA_PROGRESS.md`.
